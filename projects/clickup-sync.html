ClickUp sync pipeline

An Azure Function that copies time entries from ClickUp into Parquet files, month by month, so reports and apps never have to call the API themselves.

Stack
Python, Azure Functions, Azure Blob Storage
Libraries
pandas, PyArrow, requests
Source
ClickUp API
Skills
Data engineering, API integration, reliability

The problem

Several tools needed the same time entries from ClickUp: reporting, and later the approval app. Pulling them straight from the API every time was slow, ran into the API's limits and meant every tool had to solve the same problem.

The pipeline fetches the data once, stores it in an analysis-friendly format, and lets everything downstream read from storage instead.

How it works

  • Three refresh strategies: the last 12 months, a custom range of months, or a full refresh of the entire history
  • The date range is split into monthly partitions, so a normal run only rewrites the months that can still change
  • Months are fetched in parallel by a small pool of workers, which keeps runs short without flooding the API
  • Each month is normalised with pandas and written as its own Parquet file in Blob Storage

Built to run unattended

  • A freshness check skips the run if the data was just synced
  • A lock in Blob Storage stops two syncs from running at once, and stale locks from crashed runs are cleared automatically
  • Every run writes its result – rows per month, duration, worker count, errors and what triggered it – to a latest-run file and a history log
  • A status endpoint reports the last run, so other tools can check before they read

Structure

A coordinator runs the sync and delegates to small, single-purpose services for partitioning, fetching from ClickUp, writing Parquet, run metadata and locking. Configuration comes from environment variables, so the same code runs locally and in Azure.
