Approval and invoicing app

A web app where project managers approve each project's hours month by month and send them on to timesheets and invoices.

Year
2026
Stack
Python, Azure Functions, Jinja, JavaScript
Storage
Azure Table Storage, Blob Storage
Integrations
ClickUp, Power Automate, e‑conomic
Skills
Full-stack development, process design, data modeling

The problem

Every month, the hours logged in ClickUp have to be checked, approved and invoiced – project by project. Projects follow different rules: hourly rates, budgets, prepaid hour packages, and customers who want a timesheet with their invoice. Doing that by hand across many projects took time and was easy to get wrong.

How it works

  • For each project and month, the app builds an approval from the time entries the sync pipeline stores, combined with project data from ClickUp
  • Project managers approve the hours, adjust how many to invoice and add a comment
  • Each approval moves through clear statuses, from pending and ready to approved, sent to a draft invoice and invoiced
  • Several months can be combined into one invoice or one timesheet
  • Prepaid hour packages are synced from ClickUp and invoiced on their own

Connected to the rest

  • Approving, invoicing and sending timesheets trigger Power Automate flows, which create the timesheets and draft invoices
  • If a flow fails, the approval is left unchanged and the user gets a clear error, so nothing is invoiced twice or lost
  • Project details such as customer, product and invoice text travel with each project, so invoices come out right

Architecture

One Azure Function app serves both the API and the interface: a Jinja template with plain JavaScript on the front end, and HTTP endpoints behind it.

The code is split into repositories over Azure Table Storage, services for each workflow, and a small JSON cache in Blob Storage that keeps the app quick and can be refreshed on demand.
