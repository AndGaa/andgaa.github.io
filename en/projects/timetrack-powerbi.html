Time tracking report

A Power BI report that shows where project hours go – billable time, budgets, prepaid hours and invoicing – for project managers and leadership.

Stack
Power BI (PBIP in Git), DAX, Power Query (M), Power Automate
Data
ClickUp and e‑conomic via Azure Data Lake, budgets from SharePoint
Size
11 pages, around 160 measures
Role
Data analyst

The problem

The business had no clear view of how time was spent across projects and tasks. Hours were logged in ClickUp and invoicing lived in e‑conomic, so answering simple questions – which projects are over budget, how much of our time is billable – meant manual exports and spreadsheets.

The report brings the sources together and gives project managers and leadership one place to follow time, budgets and resource use.

Key features

  • Billable versus unbillable time, filtered by date, project manager, client and status
  • Budget status per project: over, near or within budget
  • Drill-through from the overview to a single project and the people working on it
  • Pages for people, prepaid hours, finances, hourly rates and printable timesheets
  • Role-based access, so each person sees the data they should
  • On-demand refresh from the report through a Power Automate flow

The model

ClickUp is the team's project tool, and its structure of spaces, folders and lists doesn't match the project structure needed for reporting. Project metadata is kept in ClickUp in its own pseudo-structure and linked to tasks and time entries through a bridge table.

Around that sit invoices and prepaid hours from e‑conomic, budgets from a SharePoint workbook, users and one shared calendar. That makes it possible to follow hours and money by project, client and employee. The report is saved as a Power BI project (PBIP), so the model and every measure are versioned in Git.

How it grew

The first version called the ClickUp and e‑conomic APIs directly from Power Query. The ClickUp API limits how much a single request returns, so I added pagination and staged the time entries before reshaping them. It worked, but every refresh got slower and more fragile as the history grew.

So I moved the extraction out of Power BI and into the ClickUp sync pipeline. The report now reads Parquet and JSON files from Azure Data Lake, and the time entries use incremental refresh, so only recent data is reloaded. The same files feed the approval app, so both tools show the same numbers.
